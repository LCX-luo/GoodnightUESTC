# 电脑微信授权组件接入与验证

日期：2026-10-24。仅电脑端；Android 未修改。

## 实现

- `setup_wechat.py` 固定上游提交，下载独立 Python 3.13 环境与依赖，不更改系统 Python 或原项目 Python 3.10 环境。
- `wechat_worker.py` 使用上游 SDK，避免导入或运行会直接签到的上游 main.py。学校侧 HTTP transport 仅允许查询两个平台的身份、check-bind 和 checkin-ticket；签到与填报在发送前拦截。
- `wechat_auth.py` 通过子进程标准输入输出传递授权材料，命令行不含凭据。微信凭据使用项目 Vault 加密保存。核对浏览器学号、微信绑定身份，防止账号切换时把旧票据写入新会话。
- 页面新增微信授权、取消和清除入口。状态接口不包含 Cookie、code、票据或微信 token；仅在等待扫码时展示授权二维码。
- 本地票据最多缓存 5 分钟，不声称这是服务端有效期。配置微信授权后，提交时可在本地缓存到期后重新取票；无凭据时要求人工授权。
- 一旦发送签到请求就清除本地操作票据。46004 按结果待确认处理并回查，维持原有一次提交和结果复查机制。

## 已完成检查

- 本项目 69 项回归测试通过，包括加密保存、状态脱敏、账号切换、账号隔离、票据消费和 46004 不重试。
- 独立 Python 3.13 下，新增 4 项协议适配测试通过：不同 code、两类 SESSION 隔离、身份不匹配时停止、误调用写接口也不能联网，以及静默模式不擅自启动二维码。
- Edge 页面测试通过：地图、位置保存、只读自检、模拟确认提交、移动端布局和浏览器脚本错误检查。全部学校提交响应为模拟，没有真实签到。
- 上游 103 项测试实际运行：94 通过，9 失败。失败涉及 Windows 下符号链接/文件权限，以及其 main.py 用未关闭的临时文件进行 os.replace 导致 WinError 32。当前接入没有使用上游 main.py 的缓存或 CLI 导出路径，使用本项目关文件后替换的加密存储；本项目相关测试已通过。不能据此写成“上游全部测试通过”。
- 本机服务已启动，仅监听 127.0.0.1:8090；只读状态检查确认运行环境就绪。

## 已完成的真实授权验证

用户已在网页完成本人微信扫码授权。第一轮真实测试完成学校身份核对、两个非空且各 32 字符的新 code，以及学校签发的 43 字符操作票据。

随后重启本机服务，再次发起授权测试。加密凭据成功恢复，没有再次扫码；第二轮同样取得两个 32 字符 code 和一个 43 字符票据，并在本地比较确认其与第一轮不同。仅保存脱敏统计到 `private-data/native-auth-reuse-result.json`，不输出原始凭据。两轮均未调用签到或填报接口。

同期只读查询：业务日期 2026-10-24、当天状态 PENDING、学校时段 21:00–23:30、当前时段未开放，配置点位于返回的允许范围内。范围判断只针对配置坐标，不能证明人员真实在场。

因此，本项目已经复现取票和跨进程重启后的授权复用；尚未验证正式提交、成功后的票据消耗、跨日及真实 token 刷新。不能把两轮取票成功表述为全流程签到恢复。

## 后续正式提交验证

### 用户要求的随机票据对照

2026-10-24 晚间，用户明确要求一次随机票据测试。使用本人现有学校 Cookie，内存中生成随机 43 字符票据，不覆盖真实票据；向签到接口发送一次空 JSON，不包含位置信息，不重试。实际响应 HTTP 200、业务码 46002、“小程序授权已过期，请重新进入打卡应用”。前后读取均为 PENDING，完整记录相同。

随机字符串同样返回“过期”，说明不能把该文案解释为该票据曾真实存在或必然通过了其他校验。此结果只证明该次无效授权被拒绝，不能证明真实票据提交成功，也不能推导全部校验顺序。

用户点击“预检查并确认签到”出现窗口外提示，来自本项目读取学校 schedule 后的本地判断；该路径在调用签到 POST 之前返回，不能作为提交接口通过验票的证据。

用户需在本机网页正常登录学校账号，并用本人微信扫码确认授权。随后观察身份核对、原生 code 和学校票据的真实结果；失败时只记录阶段、异常类别和业务码，不能保存到公开日志或分享原始凭据。

上述随机票据对照没有生成签到记录。有效票据正式提交仍受学校时间窗、实际位置、当天记录及用户确认限制；未到签到时间不代表任意提交测试没有影响。
