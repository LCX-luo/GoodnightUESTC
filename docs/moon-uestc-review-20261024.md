## 结论

新仓库补充了此前参考实现中缺失的微信取码层，电脑端恢复签到已有具体实现基础。但不能据此宣称本项目已恢复：作者报告的线上验证止于获取操作票据，我们尚未复现取票，也未验证有效票据下的新签到及结果复查。

## 代码实际做了什么

1. `src/moon_uestc/_wechat_login.py` 实现腾讯扫码、应用宝 OAuth 凭据交换和刷新，以及 login_buffer 请求。检查到的这些服务为腾讯域名，没有要求另行部署 YYB 服务。
2. `wechat.py:62` 把 login_buffer 和目标小程序 AppID 交给本地协议实现。`_wechat_mmtls.py:528` 包含连接、认证和 js-login 请求过程，不是仅仅把 Platform 或 UA 改成微信。
3. `main.py:326` 先用一个新 code 调用 check-bind，取得小程序 SESSION，再读取用户信息并与 H5 学校身份比较；之后用第二个新 code 请求操作票据。
4. `client.py:41`、`:62` 分别实现 check-bind 和 checkin-ticket，使用 platform-app 前缀和 mp-weixin 平台标识；业务请求继续使用原 H5 会话。
5. `main.py:348` 的 today 函数实际上会取票并提交签到，且使用写在源码中的固定坐标。函数名称不能视为只读保证，不应直接用于本人的实际签到。

## 与本地小程序源码的对应

- `app-service.js:76978`：登录时先调用微信登录，再 checkWechatBind；`:76993` 保存返回 sessionId。
- `app-service.js:55984`：取票函数再次调用微信登录；`:56000` 将新 code 提交给 `/api/auth/checkin-ticket`。
- `app-service.js:56003`：要求响应 ok；随后要求 ticket 为 43 字符的 base64url 字符串。
- `app-service.js:49159`：从存储读取 sessionId，作为 SESSION 加入请求。

因此，必须区分浏览器 H5 会话与小程序登录会话，并为两个消费步骤分别获取新 code。前端代码支持这套流程，但不独立证明第三方微信协议取码一定被服务端接受。

## 证据的层次

- 本次已确认：上述实现代码存在；本地小程序流程与其学校侧授权流程相符。
- 上游作者报告：本人账号获得两个非空、各 32 字符的 code，完成绑定查询、身份读取并取得 43 字符票据；没有提交签到或填报。见 README 的原生微信取码章节和最后的验证更新。
- 上游测试主要包含模拟 HTTP、合成加密响应及固定协议向量，不能代替线上验证。本次没有重新运行测试；本机已发现的默认 Python 为 3.10，而上游要求 3.13 以上。
- 本项目尚未证明：扫码授权完整复现、可持续刷新、首次有效提交、跨日稳定运行及微信账号安全性。

## 对现有电脑和手机程序的影响

电脑端：保留已有 CAS/Edge 登录、加密存储、地图、时段与范围检查、确认提交和结果复查；新增隔离的微信授权组件即可开展验证。上游要求 Python 3.13+，依赖 cryptography、httpx2、Pillow、prompt-toolkit、Pydantic，不应直接塞进现有 Python 3.10 环境。

手机端：现有 Java APK 不能直接运行这套 Python 协议实现。短期可考虑由电脑提供短时授权，手机保留界面；这会依赖电脑在线。若要手机独立运行，仍需移植协议及凭据管理，并验证 Android 网络与后台生命周期。本次代码审查没有证明这一移植已经完成。

## 集成前必须处理

- 首次微信扫码与学校身份匹配；无绑定时转官方绑定，禁止串用不同账号会话与票据。
- 微信凭据使用现有加密存储，不照搬 main.py 的明文 JSON 缓存。
- 票据短期使用；收到 46004 应先查询当天记录，按“已消费或结果待确认”处理，禁止盲目重试。上游 `_transport.py:21` 的票据错误集合仅含 46001/46002/46003，46004 会落入一般业务异常；本项目也需要补充这一状态。
- 保留用户确认和提交后的结果复查，不复制 main.py 的固定坐标与直接写入行为。
- HTTP 扫码/应用宝请求和 MMTLS TCP 使用不同网络路径；上游明确 TCP 阶段没有代理配置，不能据此承诺所有代理环境都能运行。
- 无 Root、无模拟器并不等于官方支持或没有风控；此前已有账号警告，不能承诺换成原生协议就安全。

建议验证顺序：离线适配与错误状态检查 → 本人扫码、只读身份核对与取票 → 有效时段和本人真实位置下，经确认进行一次提交并复查 → 再评估跨日和凭据刷新。完成取票之前不应宣布恢复，完成一次提交也不应宣布长期无人值守可用。
