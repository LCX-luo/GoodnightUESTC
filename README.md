# 晚安成电 · 本机签到

一个在本机运行的签到工具，提供 Windows 版和独立 Android 手机版：登录本人学校账号，在地图上选择实际位置，确认后向学校签到，再回读学校记录核对结果。

不需要服务器、Docker、Node.js、数据库安装或地图 API Key。Windows 版密码不落盘、Cookie 在本机加密保存；Android 版通过官方网页登录，会话保存在手机应用中。

**手机用户：** [Android APK](downloads/GoodnightUESTC-Android.apk) · [完整教程](android/README.md)。当前 0.2.1 修复扫码回调缺少 `login_type=WX` 以及授权轮询超时直接中断的问题，增加独立查询和每次确认一次提交。构建、lint、29 项真机模拟断言已通过；手机实际扫码复测仍待确认，不能用电脑成功替代手机版验证。

**多账号资料库：** 启动服务后打开 `http://127.0.0.1:8090/accounts`。顶部列出资料齐全且已保存的账号，选择后可更新登录。下方新建时依次完成学校登录、本人微信扫码、地图选点及保存位置，最后点击保存添加到库。每个账号独立加密保存，资料库不提供签到接口。见 [账号与 ESP32 进度](docs/accounts-and-esp32.md)。

**ESP32：** 实物为 ESP32-D0WD-V3、4MB Flash。原生取票与现有空调遥控工程的合并代码正在隔离构建，未刷写、未验证设备独立取票或每日调度。请勿把计划中的 21:10 任务当成已经部署。

## 电脑微信授权实验（2026-10-24）

新增独立的微信授权组件，参考 [MioYiSama/moon-uestc](https://github.com/MioYiSama/moon-uestc)，固定在提交 `f8a93c3bc4d62cea879b76560c49c9646387b386`。保留原电脑程序的 Python 3.10+ 环境，另装隔离的 Python 3.13 和上游依赖。它使用第三方微信协议，不需要 Root 或模拟器，但不保证没有微信风控、永久免扫码或持续可用。

Windows 首次运行 `python setup_wechat.py`（需要 Git 和网络），然后启动原程序。所有下载放在被 Git 忽略的 `private-data` 下；不修改系统 Python 或 PATH。上游源码单独拉取，不包含进本项目发布包。

1. 用 Edge 登录本人学校账号。
2. 点击“微信授权并测试取票”，用绑定该学校账号的本人微信扫码确认。
3. 测试会核对学校身份、先用一个新 code 建立小程序会话，再用另一个新 code 换取操作票据。测试进程禁止调用签到、填报等业务写接口。
4. 成功时仅显示票据长度、身份核对结果和未提交状态；凭据与票据加密保存。票据本地最多暂存 5 分钟，这是保守缓存策略，不代表测得学校有效期。
5. 正式签到仍须本人确认实际位置及最终提交。每次最终确认都会用已保存微信授权重新取一张票据；授权失效则提示重新扫码，不自动重新授权或重发签到。

收到 `46004` 按“已消费或结果待确认”处理，先回查学校记录。已发送请求后会清除本地票据，禁止直接复用。清除本机会话也会清除本地微信授权；这不等于在腾讯服务器撤销授权。

已用本人账号完成两轮真实取票：每轮两个 32 字符 code、一个 43 字符票据；程序重启后无需再次扫码，第二轮票据与第一轮不同。2026-10-24 在本人明确授权后完成一次正式签到：学校接受请求，回读为 `CHECKED_IN`，程序确认成功；仅发送一次，没有重试。仍未验证跨日运行和真实 token 刷新，不代表所有账号或设备均可用。Android 0.2.1 已完成本地修复与真机模拟测试，真实手机授权和签到待复测。见 [接入验证记录](docs/wechat-companion-validation-20261024.md) 和 [源码分析报告](docs/moon-uestc-review-20261024.md)。不要直接运行上游 `main.py`：该入口会用源码中的固定坐标提交签到。

## 先前兼容性限制与测试记录（2026-10-23）

学校实际提交接口返回过 `46001：请从微信小程序重新进入打卡应用后提交`。当前官方 H5 从入口的 `checkinTicket` 参数接收操作票据，存入页面会话，并通过 `X-Checkin-Ticket` 请求头提交；有效登录 Cookie 本身不能替代该授权。当前没有验证通过独立脚本或 APK 获取该票据的官方流程。

Windows 源码已支持使用与本人会话一并加密保存的合法操作票据，缺少票据时在提交前停止。登录窗口仅在学校官方 H5 页面读取已有的授权，不生成票据，也不保证普通 Edge 登录会取得票据。

新增 [MuMu 会话读取与电脑 HTTP 请求](docs/mumu-session.md)：在已 Root 的 MuMu 测试实例正常打开本人官方小程序后，电脑可读取学校票据和 Cookie，不需要操作真实手机。已验证电脑请求带票据返回 `4006：今日已完成打卡`、不带票据返回 `46001`；相同票据重复使用以及同账号另一有效会话配对也返回 `4006`，原记录未改变。**尚未验证首次创建新的签到记录，不能宣称端到端签到已经通过；完整有效期和成功提交后的消耗规则未知。** [前端证据](docs/ticket-evidence.md)。

以上为旧版排查记录。当前 Android 0.2.1 已增加取票，但真实手机端到端复测尚未完成；旧结果不能当作现版本的完整验证。

## 快速开始

### 源码运行

基础界面需要 **Python 3.10+** 和 **Microsoft Edge**；微信取票组件还需要首次安装时可用的 Git 和网络。拉取后先执行以下初始化，再启动：

```powershell
git clone https://github.com/LCX-luo/GoodnightUESTC.git GoodNightUESTC
cd GoodNightUESTC
python bootstrap.py --install-only
.\.venv\Scripts\python.exe setup_wechat.py
.\start.cmd
```

首次启动会自动创建独立 `.venv` 并安装四个直接依赖，随后自动打开 http://127.0.0.1:8090/ 。首次安装需要联网，后续启动复用环境。保持启动窗口运行；关闭窗口即停止本机服务。不要在公共电脑上保存会话。

也可手动运行：

```powershell
python bootstrap.py
```

项目已在当前电脑安装好自己的 `.venv`，不依赖父目录中的旧项目。

### 无 Python 的用户

维护者可分发 `GoodNightUESTC-Windows.zip`。旧打包程序可能不包含最新微信授权运行时，不能只靠解压旧 ZIP 恢复签到。当前优先按源码教程初始化；本次按要求不另发布便携压缩包。

本仓库提供 `build-windows.cmd` 和 GitHub Actions 构建流程，构建包默认不包含任何私人数据。可执行文件未经代码签名，Windows 可能提示未知发布者。当前仅验证 Windows，不宣称其他系统可直接运行。

## 使用流程

1. 在本机页面输入本人学号和学校统一认证密码，点击“用 Edge 登录并导入”。
2. 独立 Edge 窗口会自动填写官方登录页；本人按学校提示完成验证码、短信或二次验证。程序自动进入智慧学工、验证会话，随后加密保存 Cookie 并关闭窗口。不需要手动寻找 Cookie。
3. 点击“微信授权并测试取票”，用已绑定该学校账号的本人微信扫码并确认，等待取票成功。首次需要扫码，凭据有效时可复用刷新；不保证永久有效。
4. 点击地图选择本人实际位置，或输入经纬度及坐标系，点击“保存位置”。
5. 点击“查询”只读查看学校当天状态、时段和范围，不发送签到。
6. 点击“签到”，核对坐标并勾选实际位置，再点击“确认并提交签到”。这一步独立于查询：已有记录、时段未开放或范围检查结果都不会由本地提前挡住此次手动提交，业务条件由学校判断。确认令牌仍绑定当前账号、位置及日期，120 秒内单次使用。
7. 每次最终确认会申请新票据，只发一次 POST、不自动重发，并显示学校实际业务码、返回文字及回查状态。若取票、登录或网络失败，可能未送达，不能保证每次点击都完成服务端验票。

界面会区分“学校接受本次请求”与“查询发现已有记录”；后者不能证明本次票据有效。响应不明时先查询官方记录，下一次手动确认仍可能创建真实记录。工具不自动提交报告，当前网页版没有每日定时任务。电脑本人账号已完成一次真实签到；跨日运行和真实 token 刷新尚未验证。

## 地图与坐标

使用 Leaflet 1.9.4 和 OpenStreetMap 底图，显示署名，正常使用浏览器缓存，不批量下载瓦片。

- 默认查看沙河校区，右上角可切换沙河与清水河；切换视图不会修改已保存的位置。
- 鼠标位于地图内时，滚轮缩放地图；地图外滚轮正常滚动页面。
- 地图 / GPS：WGS-84，点击地图后自动选择此坐标系。
- 高德：GCJ-02，手动输入时选择 GCJ-02。
- 学校接口使用 GCJ-02：WGS-84 做离线近似转换，GCJ-02 原样使用。GCJ-02 在 OSM 上展示时做近似反算。
- 地图加载需要联网；底图不可用时仍能手动输入坐标。
- 选点是用户配置，不代表实时 GPS。请求里的定位精度、定位耗时均为 0，网络类型标为 unknown，不伪称设备测量数据。

页面保留两个独立测试按钮，均不调用签到接口：

| 测试 | 访问学校 | 创建签到记录 |
| --- | --- | --- |
| 离线自检 | 否 | 否 |

离线自检检查坐标转换和诊断传输层的写入拦截，结果包含 `schoolRequests: 0`、`schoolWrites: 0`、`submitted: false`。在线只读检查显示学校当天已有记录、时段与所选位置是否在范围内；学校可能记录访问日志，但此操作不创建或修改签到记录。

`ReadOnlyTransport` 始终禁止业务 POST。实际签到使用单独的 `SubmissionTransport`，仅允许精确的签到路径、一次 POST，且只能在本地确认令牌与本人位置确认有效后使用；时段、范围和重复记录由学校判断。登录窗口允许学校认证请求，但不允许智慧学工业务写入。

## 重复提交与结果不明

手动签到不再按日拦截。每次新的最终确认最多发送一次请求，旧确认令牌不可重放；同一请求不会因为超时自动重发。提交前会取得新操作票据，发出请求后清除本地票据。

学校当天已有记录与本次请求返回值分别展示。学校明确拒绝时显示业务码和学校提示，即使回查发现 `CHECKED_IN`，也不会把这次拒绝显示成成功。若学校返回成功但回查失败，显示接受后待确认；断网响应不明时先查询官方记录。

## 私有数据

源码运行的数据位于项目 `private-data/`；可执行版本的数据位于 exe 同目录的 `private-data/`。

- `session.enc`：AES-GCM 加密的 Cookie、浏览器标识及账号。
- `dashboard.key`：本机加密密钥，不要与数据库/会话一起分享。
- `location.json`：用户选择的位置。
- `attempts.sqlite3`：旧版按日提交保护记录，新版手动提交不据此拦截。
- `wechat.enc`：加密微信授权材料。
- `profiles/`：资料库各账号独立加密资料。

密码只在本次登录过程中使用，不写入配置或日志。网页不返回 Cookie 原文。“清除本机会话”会清除本机微信授权，不会影响你日常 Edge 的登录。

`.gitignore` 排除了私人数据、虚拟环境、日志和构建产物。不要手动把这些资料添加到 Git。服务只监听 `127.0.0.1:8090`，有 Host、Origin 和 CSRF 检查，不对公网开放。

## 构建与维护

双击 `build-windows.cmd`，或：

```powershell
python bootstrap.py --install-only
.\.venv\Scripts\python.exe -m pip install "pyinstaller>=6.0,<7"
```

## 连接速度与进度

学校请求和独立登录窗口默认自动选择路线：没有系统代理时直接连接；检测到代理时，优先快速直连并在必要时并行探测代理，缓存可用路线。系统代理开关或地址变化后重新选择。只读请求遇到网络失败可切换路线，真实签到 POST 永不自动重发。工具不会修改系统代理设置。可选地设置 `UESTC_NETWORK_MODE=direct` 或 `UESTC_NETWORK_MODE=system` 固定路线；旧的 `UESTC_USE_SYSTEM_PROXY=1` 仍兼容。

登录验证只读取一次学校记录；正常会话不再重复进入业务入口。确认签到复用已确认的地址，仍保留提交前的当天记录、位置范围和时段校验。页面显示具体阶段和已用时间。结果不明时只复查，不自动重发。
