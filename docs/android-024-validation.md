# Android 0.2.4 真机验证（2026-10-24）

本次用户在真实 Android 16 手机上操作，应用版本为 0.2.4、versionCode 7。没有 Root、模拟器、注入或证书替换。以下仅记录脱敏阶段和结论，不附原始账号材料。

## 实际通过的流程

首次授权阶段为：学校身份核对 → 二维码等待 → 轮询连接异常 `qr_connection_failed` → 保留原二维码有限重连 → 收到微信授权 → 应用宝回调 → 加密保存凭据 → 建立小程序会话 → 身份核对 → 学校操作票据取得。

之后又观察到 `allowQr=false / cached=true` 的一次取票成功。这证明凭据保存后，应用可在该次测试中免重复扫码重新取票；不能据此承诺刷新永久有效或所有网络均可用。

页面显示“微信授权成功……票据已取得，没有提交签到”。只读查询显示当天 `CHECKED_IN`。**已有记录不能证明本次 Android 创建了签到；手机新建签到记录尚未验证。**

## 修正过程与证据边界

- 修复扫码回调缺少 `login_type=WX`，以及长轮询超时直接中断。
- 授权任务改由应用进程持有，Activity 重建不再取消；返回前台重放同一二维码和阶段。38 项设备模拟断言包含真实 Activity 重建。
- 旧版失败日志只定位到二维码等待，不能全部归因于生命周期。手机未开启“不保留活动”。最终成功轮次明确观察到连接异常后重试恢复。
- 同一二维码在 210 秒总期限内对短暂断连、超时和服务端 5xx 最多重试三次；4xx 和证书校验失败明确停止，不关闭 HTTPS 验证。
- 应用私有诊断环日志只记录固定阶段、异常类型及受限错误码，不记录账号、二维码、URL、Cookie、code、票据或原始异常文本。

构建和 lint 通过；38 项设备模拟断言及 11 项桌面协议模拟测试通过。模拟测试没有向学校提交签到。

## 使用

学校登录后点击一次“显示二维码 / 验证授权”，用绑定当前学校账号的本人微信扫码并确认，返回 App 等待最终结果。当前二维码要求摄像头扫描，不保证同机相册可用；未实现直接跳微信完成授权。

返回时二维码消失可能是授权已进入后续阶段，也可能是失败结束，应看最终状态。不要连续生成新二维码覆盖原任务。整个进程被系统结束时无法保持原网络请求，应用会提示重新授权。

“查询”只读；“签到”经本人确认后取新票据并提交一次请求，不按当天已有记录在本地拦截、不自动重发。学校返回码与当天记录分别展示。使用实际位置，结果以学校为准。
